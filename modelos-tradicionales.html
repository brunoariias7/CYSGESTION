MODELO 01

Modelo Cascada

El modelo Cascada organiza el desarrollo en etapas consecutivas. Cada etapa se completa antes de comenzar la siguiente. Por eso, el proyecto suele planificarse desde el principio y se busca conocer los requisitos antes de iniciar la construcción.

¿Cómo se organiza?

  1. Requisitos: se identifican las necesidades del usuario.
  2. Análisis y diseño: se define cómo será el sistema.
  3. Implementación: se escribe el código.
  4. Pruebas: se comprueba el funcionamiento y se buscan errores.
  5. Entrega y mantenimiento: se pone en uso y se realizan correcciones.

✓ Ventajas

  • Es sencillo de entender y organizar.
  • Sus etapas y objetivos están definidos.
  • Facilita la planificación inicial.

✗ Desventajas

  • Es difícil volver atrás y modificar etapas terminadas.
  • Los cambios de requisitos pueden generar demoras y costos.
  • El usuario suele ver el producto funcionando al final.

📌 ¿Cuándo se utiliza?

Puede utilizarse cuando los requisitos están claros desde el comienzo, el alcance es estable y se esperan pocos cambios durante el proyecto.

MODELO 02

Modelo V

El modelo V es una variante del desarrollo secuencial. Su característica principal es que relaciona las etapas de definición y diseño con actividades de prueba. Mientras se planifica una parte del sistema, también se piensa cómo se va a verificar.

¿Cómo se organiza?

  1. Requisitos: se establecen las necesidades y criterios de aceptación.
  2. Diseño del sistema: se define la estructura general y se planifican pruebas del sistema.
  3. Diseño detallado: se definen los componentes y sus relaciones.
  4. Codificación: se desarrolla el software.
  5. Pruebas: se realizan pruebas unitarias, de integración, del sistema y de aceptación, relacionadas con las etapas anteriores.

✓ Ventajas

  • Las pruebas se consideran desde las primeras etapas.
  • Relaciona cada etapa de desarrollo con su verificación.
  • Ayuda a detectar problemas y organizar el control de calidad.

✗ Desventajas

  • Es poco flexible cuando aparecen cambios.
  • Necesita una planificación detallada.
  • Modificar etapas anteriores puede afectar las pruebas previstas.

📌 ¿Cuándo se utiliza?

Es útil en proyectos donde la verificación y la documentación son importantes y se necesita comprobar que cada requisito se cumpla, por ejemplo, en sistemas industriales o de seguridad.

🔄

MODELO 03

Modelo Iterativo e Incremental

Este modelo construye el producto mediante ciclos de trabajo. En cada iteración se revisa y mejora lo realizado, y de forma incremental se agregan nuevas partes o funcionalidades. Así, el producto evoluciona en lugar de desarrollarse completo en una sola entrega.

¿Cómo se organiza?

  1. Versión inicial: se define una primera versión o producto mínimo.
  2. Planificación: se eligen las mejoras o funcionalidades siguientes.
  3. Desarrollo y pruebas: se construye y verifica el incremento.
  4. Revisión: se analiza el resultado y se recibe retroalimentación.
  5. Nueva iteración: se repite el ciclo para mejorar y ampliar el producto.

✓ Ventajas

  • Permite entregar partes funcionales antes de terminar todo el producto.
  • Facilita incorporar cambios y comentarios.
  • Los errores pueden detectarse en cada ciclo.

✗ Desventajas

  • Necesita coordinación y revisión en cada iteración.
  • Puede ser difícil estimar el alcance y el tiempo total.
  • Los cambios continuos requieren controlar las versiones.

📌 ¿Cuándo se utiliza?

Se utiliza cuando el producto puede construirse por partes, se espera aprender durante el desarrollo o los requisitos pueden cambiar y ampliarse con el tiempo.
